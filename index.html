导入格式 & 让 AI 帮你转换

① 导入的格式

导入的是一个 JSON 文件，结构长这样：

{
  "app": "copie",
  "version": 3,
  "entries": [
    {
      "title": "条目标题",
      "tags": ["分类标签", "可选"],
      "blocks": [
        {"key":"名字","value":"AA"},
        {"value":"没有键名时，内容块会铺满整行"}
      ]
    }
  ]
}

blocks 里的每一项都可以有可选的 key 和必填的 value。键名仅用于显示；复制时始终只复制 value。旧版的字符串数组仍可直接导入。

② 让 AI 帮你转

复制下面这段发给任意 AI，末尾贴上你的内容，它就会吐出能直接导入的 JSON：

请把我下面的内容整理成 Copie 复制箱的导入 JSON。
格式：顶层对象 {"app":"copie","version":3,"entries":[...]}；
每个 entry = {"title":"条目标题","tags":["可选标签"],"blocks":[{"key":"可选键名","value":"一段可复制文本"},{"value":"另一段"}]}。
规则：blocks 每项的 value 是「点一下就整段复制」的内容（API key、人设、baseurl 等）；key 可省略，仅作左侧显示；省略 key 时 value 正常铺满整行。相关内容放进同一 entry 的不同 block；tags 用来分类，可省略。
只输出 JSON 本身，不要任何解释或代码块标记。我的内容：

云同步 · 教程 & 原理

一句话

数据加密后才上云，云端只见密文。打开 App 先读本机；同步时逐条合并（按条取新、删除也会同步），不会整份覆盖。

① 怎么开（只需一次）

  1. 先建仓库：打开 github.com/new，仓库名填 copie-data，选 Private（私有），创建（空的就行）
  2. 生成 token：打开 github.com/settings/tokens → Fine-grained tokens → Generate，Repository access 选 Only select repositories → copie-data，Permissions 只给 Contents: Read and write，生成后复制
  3. 把 token 粘到上面第一个框，第二个框设一个主密码（加密用，你自己记住）→ 点连接并同步

② 换设备

新设备打开同一网址 → 云同步 → 填同一个 token + 同一个主密码 → 连接并同步 → 数据自动拉过来并解密。

③ 同步逻辑

  • 加密：上云前用主密码把整份数据加密（AES-GCM），GitHub 上只存密文，拿到 token 或仓库也读不出内容
  • 启动本地优先：打开 App 先显示本机数据，然后顶部弹"自动同步中"，在后台逐条合并；关掉「自动同步」就只在点「立即同步」时同步
  • 逐条合并：同一条谁改得晚用谁的；一边有另一边没有的补上；在某台设备删掉的条目会带"删除记录"，其他设备同步后也删，不靠整份覆盖
  • 自动上传：开着「自动同步」时，改动停手 1.5 秒后做一次同样的合并同步；关掉就纯手动
  • 安全阀：同步会让本机少掉一半以上条目时先问你；本机为空却要清掉云端也会先问；同步前自动留本机快照
  • token 和主密码都只存本机浏览器，不进代码、不上云

注意

• 主密码丢了，云端数据永远解不开——请务必记牢（本地 App 里的数据不受影响）
• token 只授权 copie-data 这一个仓，泄露了也碰不到你别的仓库；建议设过期、定期换
• 要联网、在网址(https)下才通
• 云端仓库 copie-data 每次上传都是一次 git 提交，历史都在，误删也能从旧提交里找回
• 别人的改动是"打开 App 那下"才拉取，不是实时对推
